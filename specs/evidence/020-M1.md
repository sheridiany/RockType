## 本次交付

现有 `RoarkTRegisterInputSource` 增加两个只读子命令，均不调用注册、启用、选择或重启 API：

```sh
# 当前用户已安装输入源的现场状态；无需安装本工具。
./dist/RoarkTRegisterInputSource diagnose-icons

# 指定构建产物的两个模式、三个资源声明；不会注册该 bundle。
./dist/RoarkTRegisterInputSource check-icons './dist/RockType Input.app'
```

- JSON 输出当前两个模式的 enabled/selected/selectable、IconRef 是否存在、TIS 图标 URL、栅格化及非空检查、LaunchServices 路径。
- 若已有辅助功能访问权限，读取 TextInputMenuAgent 的额外菜单项数量及位置/尺寸；不请求权限、不读标题/输入字段、不截屏。没有权限时明确输出不可用。
- `resourceCheckPassed` 与退出码仅表示资源检查是否完成并通过，**不代表屏幕上的图标可见**。IconRef-only 情况明确标为未验证，不把非空指针当成成功渲染。
- 全量测试通过现有 `MenuIconTests` target 执行新检查；使用临时合成 bundle，验证缺失文件、透明 PDF、正常 PDF、单模式替代图标缺失、目录越界及错误 bundle 身份，并确认检查前后文件不变。

## 交给 main 的现场步骤

本次诊断无需安装输入法即可使用；main 合入后构建获得工具。需要安装的后续修复只能从 main 执行。

1. 图标正常时运行 `./dist/RoarkTRegisterInputSource diagnose-icons > .build/m1-normal.json`，同时记录时间及当前使用的是内屏还是外屏。
2. **下一次消失时先保留现场，不重启 TextInputMenuAgent、不重新登录、不重装、不切换输入源来恢复。** 立即运行同一命令，保存到 `.build/m1-missing.json`，记录退出码。人工记录是整个菜单项消失，还是位置仍在但图形空白，以及当时打字是否正常。
3. 记录消失前最近一次操作：输入源切换/Caps Lock、输入法重启或异常、主 App 重启、设置保存/部署、锁屏/睡眠唤醒、显示器变化，或 main/worktree 构建/安装。暂不认定任一项为根因。
4. 若诊断资源失败，比较缺失模式、TIS URL 与 LaunchServices 路径；若资源正常但菜单项消失/零尺寸，转向系统菜单生命周期；若两者均正常而图形空白，需在该现场检查系统渲染/缓存。工具报告不能替代这一人工可见性判断。
5. 捕获现场后再选择单一触发因素复现并修复。安装路径确有“退出输入法 → 删除整个目标 bundle → ditto → 每次 register”的空窗，但本次没有证明它导致了用户报告的数小时后复发，未据此提交猜测性安装重构或版本号变更。
