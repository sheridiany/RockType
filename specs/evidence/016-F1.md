# SPEC-016 F1 · 截图无感进入

日期：2026-10-11。分支：`agent/xpc`。开始时合并 main `0f45fc2`；提交前再次合并 main `65a5a23`（含 SPEC-015 与 F2），最终门禁基于该合并结果。关联 FR-D1、NFR-4/5/6/7。

## 定位与结论

- **已复现的时序缺陷**：`capture()` 在等待异步 SCK 截帧前就对自身可见浮窗 `orderOut`，预览和历史也立即关闭。通过真实协调器入口、可记录窗口调用的 NSPanel 和注入的采样函数，旧代码在采样刚开始时已经隐藏一次窗口。这样会先露出实时桌面，再显示冻结遮罩，存在可见的空档。SCK 原本就按应用排除自身，不必为排除像素而提前改动实时桌面。
- **其他入口风险**：旧代码在每块屏幕准备完后立即显示，并在鼠标所在屏幕调用 `NSApp.activate()`，可能影响前台应用、菜单栏、全屏/Space；遮罩的 `animationBehavior` 仍为系统默认。自动检查确认旧配置不是 `.none`，但这不等于已实测系统必然播放淡入。
- **排除的合成假设**：修改前后，冻结底图在 1×、2×、左上和右下非零屏幕原点均与同一合成源逐通道一致，偏移 **0 px**。没有据此修改 backingScale、坐标映射或底图绘制。
- 这些证据定位了可复现的入口时序缺陷和可移除的激活/动画风险；尚未在用户安装版本上录制真实进入过程，不能宣称已证明用户机器上“晃动”的唯一原因，或真实观感已验收。

诊断闭环：`swift test --filter CaptureEntryTests`。修改前两项失败（采样前隐藏、默认动画），修改后 F1 五项回归通过。日志 `.build/f1/{red,before,lifecycle,focused}.log`。

## 实现

- 采样等待期间保留自身浮窗；预览、历史延迟到遮罩接管后才关闭。采样失败或取消不额外隐藏/恢复这些窗口。
- 所有屏幕先构造完整 Canvas，创建过程禁用 Core Animation 隐式动作，再统一布局、显示内容并提交图层。短暂屏幕更新抑制仅包住同步呈现阶段，`defer` 保证恢复，不跨越异步采样、网络或 AX 等待。
- 所有遮罩 `orderFront` 后才隐藏自身浮窗，避免提前露底；最后让鼠标所在屏幕的非激活 NSPanel 成为 key 并指定 first responder。
- 进入不再调用 `NSApp.activate()`；窗口动画明确 `.none`。沿用全屏/多 Space 的窗口配置，遮罩直接出现，底图不做淡入、缩放或位移动画。
- 取消时由非激活面板归还借用的键盘焦点；仅当后续原生对话框确实使本 App 激活时，才显式恢复有效来源应用。已关闭的预览/历史不加入浮窗恢复列表。
- 拒绝空帧结果；保留原有安全输入、密码框、权限、代次及迟到结果保护。

生产修改仅 `ScreenshotCoordinator.swift`（含 CapturePanel）与 `CaptureOverlayGroup.swift`。不修改 F2 的 `CaptureCanvas.swift` / `CaptureToolbar.swift` / `ScreenshotSymbols.swift`，不修改 F3 的文字编辑或标注样式。
