# SPEC-020 M2：撤销旧 plist 门禁，按公开 TIS 状态验收

- 基线：先 `git merge main`，fast-forward 到 `796a961`。
- **已修复 M1 验证器把健康系统误判为失败的问题。重装后十次点击仍待 main 真机验收；未宣布原始图标故障已根治。**
- 没有安装、注册、启用、禁用、选择真实输入源，没有清理缓存、直接写系统偏好或重启任何系统进程。

## 推翻上一轮判据

用户已在系统设置删除并重加 RockType，确认点击图标正常；旧 `com.apple.HIToolbox` 的 AppleEnabledInputSources 仍缺少它。旧签名工具在这个健康现场 `verify-enabled` 退出 1。该判据是我们的错误，不能将缺项解释为持久化丢失或据此重复启用。

本轮找到本机 macOS 27 的第三方存储：

- CFPreferences 域 **`com.apple.inputsources`**，键 **`AppleEnabledThirdPartyInputSources`**。
- 本机有 `~/Library/Preferences/com.apple.inputsources.plist`；通过只读 CFPreferences 查询，匹配到 RockType 的 `Keyboard Input Method` 父记录和 `Input Mode` / pinyin 记录。
- HIToolbox 的 `_CopyInputSourceEnabledPrefs`、`_GetInputSourceEnabledPrefsIncludingThirdParty` 内部代码区分旧列表与第三方列表；对应域/键字符串与上述只读结果一致。探针只读取已加载系统映像中的静态字符串，未执行私有写入函数。证据 `.build/m2/preference-keys.m`、`third-party-prefs.{swift,log}`。
- 只读系统菜单消费者现在包含 ABC、RockType pinyin、CharacterPalette；排序列表包含 ABC 与 pinyin。`.build/m2/ui-source-list.log`。上一轮故障时排序列表只有 ABC 的观察仍有效，**但不能用旧 HIToolbox 缺项解释它**。
- 仅本机 macOS 27 实测，未实测 macOS 26；没有把新发现的私有 schema 再做成安装硬门槛，也没有断言 HIToolbox 的其他键全部停用。

## 修复

1. `verify-enabled` 用公开 TISCreateInputSourceList 与 TISGetInputSourceProperty 校验：父源注册且 enabled，pinyin 注册、enabled 且 select-capable。父源自身不可选择是正常情况；双拼未启用也不导致失败。输出 registeredIDs、enabledIDs、selectableIDs、verificationPassed。
2. `ensure-enabled` 完全移除偏好文件依赖。注册信息完整时不重复 Register；父源/pinyin 已启用时不重复 Enable。必要时仍按父源→模式启用，最后由新进程执行 TIS 验证。保留 API 报错及“API noErr、真实状态仍不满足”的失败处理，不调用 Select。
3. dev/pkg 安装仍使用 ensure + 独立 verify；本轮修正安装成功提示和 FR-F3/README，移除“已验证持久化”的不实承诺。
4. diagnose-icons 的 `enablement` 给出公开 TIS 状态。`preferenceEvidence` 分别展示旧 HIToolbox 与第三方配置的匹配情况，并标记 `authoritativeForVerification=false`。偏好不可读、布局变化或旧列表缺项不会影响 TIS 验证结果。资源检查退出码仍只表示资源有效，不代表图标可见。

- 七项定向测试通过，包括：旧偏好为空而 TIS 健康时不注册/启用；父源不可选且双拼未启用仍通过；父源或 pinyin 未启用、模式不可选、未注册时拒绝；启用顺序、API 失败和新进程复核失败。

## 原始重装问题的调查边界

原始 dev 安装存在“删除已安装目录→复制”的窗口；早期 build 也注销同 identifier 的 IME 构建副本。这两条会改变系统可见的 bundle/注册状态的路径，已在 `d34a07a` 移除：改为同文件系统原子交换，并停止构建时注销 IME。当前健康重装不重复注册或启用。

现有证据尚不能区分：旧删除窗口、旧注销操作，或系统对替换 bundle 的身份/缓存处理，究竟是哪一步造成最初的 UI 列表遗漏。删除重加同时刷新了多层状态，不能作为其中某条触发路径的单变量证明。本轮不加入禁用重启、强制重新注册或私有缓存清理来掩盖这一未知项。

下一步最小实验正是用户指定的“一次原子重装 + 十次点击”。以下对照保留 TIS 图标 URL、LaunchServices URLs 和菜单项几何，可发现重装后仍绑定旧路径或菜单宽度收缩的问题。TIS 验证成功本身不能代替十次点击验收。

## main 真机步骤（待人工验证）

合入并构建后，在 main 执行：

```sh
mkdir -p .build/m2-acceptance
./dist/RoarkTRegisterInputSource verify-enabled
./dist/RoarkTRegisterInputSource diagnose-icons > .build/m2-acceptance/before.json
./scripts/install-dev.sh
./dist/RoarkTRegisterInputSource verify-enabled
./dist/RoarkTRegisterInputSource diagnose-icons > .build/m2-acceptance/after-install.json
```

安装前后 verify-enabled 都应退出 0，install-dev 应退出 0。旧 HIToolbox 匹配结果即使仍为 false 也不能造成失败。用户连续打开/关闭输入法图标十次，确认图标和菜单持续正常，再运行：

```sh
./dist/RoarkTRegisterInputSource diagnose-icons > .build/m2-acceptance/after-ten-clicks.json
```

若复发，记录具体时间、内/外屏、安装退出码及三个 JSON，保留现场，不先删除重加或 killall。优先比较 TIS 运行期状态、图标/LaunchServices 路径和 AX 尺寸，再核对只读第三方偏好证据，不能重新回到旧 plist 判据。macOS 26、全拼/双拼切换、睡眠唤醒属于后续兼容性验收，未在本 worktree 执行。
