## B2：改动前诊断

使用 `diagnosing-bugs`。已运行 `swift test --filter voiceBindingFailureStillStartsRecording`：**失败（预期 red）**，注入端点不可用和超时，真实 `VoiceInputController.press` 均显示“无法绑定输入位置，请选中 RockType 输入法后重试。”，录音器没有启动。`.build/b2/red.log` / `red.exit`。

代码确认的拒绝路径（按排查顺序，不代表真实发生频率）：

1. 当前不是 RockType 输入源或 IMK 控制器尚未激活：`RoarkTVoiceServer.activate` 才发布端点；端点可以不存在，或现有端点的 controller 已在 deactivate 中清空。
2. 尚有未上屏拼音：`SquirrelInputController.voiceClient` 要求 `preedit.isEmpty`；因此存在 controller 也可能没有可绑定 client。
3. 前台应用 bundle identifier 必须等于 IMK client 的 bundle identifier；不等会拒绝。Electron/WebView/终端是否触发这一条件取决于具体应用，不能凭应用类别断言其必然失败。
4. App 捕获的 PID 与服务实际处理时的前台 PID 不同会拒绝。注意服务的 context PID 来自当时前台应用，并非读取 IMK client PID；不能把该条件误述为直接比较两个进程的 client PID。
5. 发现服务/匿名端点不可用、签名连接被拒绝或超时都会失败。原客户端将多个原因归为 unavailable，控制器又把录音器启动错误也误归为绑定失败。

最近两小时对本产品 `capture refused:` 日志只做内存内分类计数：查询退出 0，但没有匹配记录。未保存原始日志、应用名称或用户内容。因此上述是代码确认及合成拒绝测试，不是现场频率调查；真实应用矩阵仍待人工。

实现决策：录音与能否绑定分开；有 IMK ticket 时只走 IMK，提交被拒/超时不再粘贴，防止重复上屏。没有 ticket 时，使用 Fn 开始时捕获的可验证 AX 输入位置作为粘贴兜底；无法安全确认位置也允许录音，最终保留结果供复制。用户本次明确授权覆盖 PRD 旧的语音“不模拟粘贴”约束。

### B2 实现与验证

- `VoiceInputController` 不再因 capture 失败中止；即使 AX 位置也无法捕获仍可录音，结束后保留完整文字。麦克风启动失败单独提示，不再冒充绑定或模型失败。
- `VoiceCommitBridge` 区分未选中输入源、发现服务不可用、端点不存在、绑定拒绝；日志仅记录枚举原因。未选中本输入源立即跳过无效发现；选中时两阶段各最多等待 350ms，避免原先最多 6 秒的绑定等待；提交仍保留原 3 秒限时。冷启动/负载下的预算适配待人工。
- `VoicePasteBridge` 捕获前台进程实例、AX 窗口/文本元素和选区（可为零长度光标），不读字段正文。填入前要求原进程仍存活、PID/应用/焦点/窗口/选区一致，范围可确认，未过 590 秒期限，目标仅消费一次。键盘或点击使来源失效，即使光标随后回到原位也不复用；自身粘贴事件带私有标记，避免误判。
- Secure Input/密码框/不可检查状态失败关闭；输出长度与控制字符/换行门禁沿用语音安全约束。不切换/激活来源应用。仅向原 PID 投递 Cmd+V，不发送 Return，也不在 IMK 提交失败后追加粘贴。
- 复用 `ReplacementPasteTransaction.shared`：与替换原文互斥；保存每个剪贴板项的全部可物化类型；写入前后校验安全/来源/所有权；350ms 消费窗口后，仅在 changeCount 和本次标记仍匹配时恢复。新复制内容优先。已投递后取消不会提前恢复导致目标读错内容，清理仍等待有界消费窗口。
